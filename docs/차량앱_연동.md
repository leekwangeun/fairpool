# 차량 앱 연동 (Kotlin)

## 결론: 동승자가 QR 페이지에서 보낸 주소를 차가 받아올 수 있나

**받아올 수 있습니다.** 확인한 근거는 다음과 같습니다.

| 확인 항목 | 결과 | 근거 |
|---|---|---|
| 차가 서버에 접속할 수 있는가 | 가능 | Pleos 에뮬레이터에서 인터넷 연결 확인(`ping 8.8.8.8` 성공, `supabase.com` 주소 풀림). 앱에는 `android.permission.INTERNET` 만 추가하면 됨 |
| 동승자가 보낸 장소를 차가 읽을 수 있는가 | 가능 | `get_trip_admin(코드, 차의 비밀값)` 이 동승자별 탈 곳, 내릴 곳을 `{label, area, address, lat, lng}` 로 돌려줌. `supabase/tests/db.test.mjs` 의 "a trip made on the car screen hands the passengers' stops back to the car as waypoints" 테스트가 이 흐름을 검증 |
| 그 장소를 내비 경유지로 넣을 수 있는가 | 가능 | NaviHelper `RequestWaypointInfo` 는 위도, 경도(WGS84), 이름, 주소를 받음. 검증 앱(`pleos-listener-test`)에서 `requestRouteWithWaypoints` 로 순정 내비가 실제 안내를 시작함을 확인 |

검토하면서 고친 점도 있습니다. 처음에는 동승자가 장소 이름만 쳐도 넘어가서 좌표 없이 저장될 수 있었습니다. 그러면 차가 경유지를 만들 수 없습니다. 지금은 두 겹으로 막습니다.
- 웹: 검색 목록에서 고른 장소만 받습니다.
- 서버: 좌표 없는 장소는 `place_needs_location` 으로 거절합니다.

남은 제약은 다음과 같습니다.
- 경유지는 최대 2개입니다. 동승자가 많으면 도착할 때마다 남은 곳으로 다시 경로를 요청합니다(기획서 3.1).
- 경유지 도착 이벤트는 에뮬레이터에서 확인하지 못해, 시연은 가짜 이벤트 소스로 합니다(검증 리포트 H2).
- 장소 검색은 지금 OSM(Photon)이라 국내 상호 검색이 약합니다. 카카오 로컬로 바꾸면 좌표 형식(WGS84)은 그대로입니다.

## 호출 방식

차량 앱은 Supabase의 REST 엔드포인트로 서버 함수를 부릅니다. Google Play 서비스가 필요 없는 Ktor Client로 충분합니다.

```
POST {SUPABASE_URL}/rest/v1/rpc/<함수 이름>
apikey: {ANON_KEY}
Authorization: Bearer {ANON_KEY}
Content-Type: application/json

{ "p_code": "SDQ6NH", "p_admin_secret": "..." }
```

응답은 JSON 객체입니다. 오류는 HTTP 400과 함께 `message` 에 `trip_not_found`, `not_allowed` 같은 코드가 옵니다.

## 1. 처음 한 번: 차량 연결

1. `create_vehicle_link` 를 인자 없이 부르면 `vehicle_secret` 과 `link_code` 가 옵니다.
2. `vehicle_secret` 은 Android Keystore로 암호화해 운전자 프로필별로 저장합니다. 다시 받을 수 없습니다.
3. 차 화면에 `https://<사이트>/link/<link_code>` QR을 띄웁니다(10분 유효). 운전자가 휴대폰으로 찍으면 연결됩니다.

## 2. 운행 만들기와 초대 QR (L1, L2 화면)

`create_trip(p_title, p_origin, p_destination, p_seats, p_rule, p_include_driver, p_vehicle_secret)` 을 부르면 새 `code` 와 `admin_secret` 이 옵니다. 차 화면에 `https://<사이트>/t/<code>` QR을 ZXing으로 그려 띄웁니다. 운행마다 코드와 QR이 새로 생깁니다. 운전자가 휴대폰에서 미리 만든 운행은 `get_vehicle_trips(p_vehicle_secret)` 로 불러옵니다.

```kotlin
// ZXing core: 카메라 없이 QR 생성만
val matrix = QRCodeWriter().encode(url, BarcodeFormat.QR_CODE, 512, 512)
```

## 3. 동승자 장소 받아서 경유지로 넣기

```kotlin
val trip = api.getTripAdmin(code, secret)              // 정차 중에만 다시 부름 (주행 중 CPU 제한)
val stops = orderStops(trip.passengers)                // 페어풀의 들를 곳 순서
val waypoints = stops.take(2).mapIndexed { i, s ->
    RequestWaypointInfo(
        s.lat, s.lng, s.label,
        if (i == 0) WaypointIndex.FIRST else WaypointIndex.SECOND,
        "", s.address ?: s.label, "0", ""
    )
}
navi.requestRouteWithWaypoints(RouteWithWaypointsRequest(destinationOf(stops.getOrNull(2) ?: trip.destination), waypoints))
```

## 4. 운행 중 진행 상황 보내기 (동승자 M2, M2-1 화면)

| 상황 | 부를 함수 |
|---|---|
| 출발 | `set_trip_status(p_code, p_admin_secret, 'in_progress')` |
| 코스, 남은 시간, 예상 몫 | `update_progress(p_code, p_admin_secret, p_progress, p_estimates)` |
| 좌석 매칭, 탑승 | `mark_passenger(p_code, p_admin_secret, p_passenger_id, p_seat, p_boarded = true)` |
| 하차 | `mark_passenger(..., p_alighted = true)` |

`p_progress` 형식입니다. 남은 시간과 거리는 NaviHelper `getWaypointInfo` 의 `remainTime`, `remainDistance` 를 씁니다. 서버가 동승자마다 남의 장소와 운전자 목적지를 가려서 보여 줍니다.

```json
{
  "car": { "lat": 37.57, "lng": 126.98 },
  "stops": [
    { "kind": "start", "label": "가평 MT 숙소", "time": "15:10", "state": "done" },
    { "kind": "pickup", "passenger_id": "…", "label": "신촌역 2번 출구", "eta_min": 10, "distance_km": 7.0, "state": "now" },
    { "kind": "dropoff", "passenger_id": "…", "label": "연희동 주민센터", "area": "서대문구 연희동", "eta_min": 25, "state": "next" },
    { "kind": "end", "label": "지훈 집", "state": "next" }
  ]
}
```
