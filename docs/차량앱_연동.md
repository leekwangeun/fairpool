# 차량 앱 연동 (Kotlin)

## 결론: 동승자가 QR 페이지에서 보낸 주소를 차가 받아올 수 있나

**받아올 수 있습니다.** 확인한 근거는 다음과 같습니다.

| 확인 항목 | 결과 | 근거 |
|---|---|---|
| 차가 서버에 접속할 수 있는가 | 가능 | Pleos 에뮬레이터에서 인터넷 연결 확인(`ping 8.8.8.8` 성공, `supabase.com` 주소 풀림). 앱에는 `android.permission.INTERNET` 만 추가하면 됨 |
| 동승자가 보낸 장소를 차가 읽을 수 있는가 | 가능 | `get_trip_admin(코드, 차의 비밀값)` 이 동승자별 탈 곳, 내릴 곳을 `{label, area, address, lat, lng}` 로 돌려줌. `supabase/tests/db.test.mjs` 의 "a trip made on the car screen hands the passengers' stops back to the car as waypoints" 테스트가 이 흐름을 검증 |
| 그 장소를 내비 경유지로 넣을 수 있는가 | 가능 | NaviHelper `RequestWaypointInfo` 는 위도, 경도(WGS84), 이름, 주소를 받음. 검증 앱(`pleos-listener-test`)에서 `requestRouteWithWaypoints` 로 순정 내비가 실제 안내를 시작함을 확인 |

검토하면서 고친 점도 있습니다. 처음에는 동승자가 장소 이름만 쳐도 넘어가서 좌표 없이 저장될 수 있었습니다. 그러면 차가 경유지를 만들 수 없습니다. 지금은 두 겹으로 막습니다.
- 웹: 검색 목록에서 고른 장소만 받습니다.
- 서버: 좌표 없는 장소는 `place_needs_location` 으로 거절합니다.

남은 제약은 다음과 같습니다.
- 경유지는 최대 2개입니다. 동승자가 많으면 도착할 때마다 남은 곳으로 다시 경로를 요청합니다(기획서 3.1).
- 경유지 도착 이벤트는 에뮬레이터에서 확인하지 못해, 시연은 가짜 이벤트 소스로 합니다(검증 리포트 H2).
- 장소 검색은 지금 OSM(Photon)이라 국내 상호 검색이 약합니다. 카카오 로컬로 바꾸면 좌표 형식(WGS84)은 그대로입니다.

## 호출 방식

차량 앱은 Supabase의 REST 엔드포인트로 서버 함수를 부릅니다. Google Play 서비스가 필요 없는 Ktor Client로 충분합니다.

```
POST {SUPABASE_URL}/rest/v1/rpc/<함수 이름>
apikey: {ANON_KEY}
Authorization: Bearer {ANON_KEY}
Content-Type: application/json

{ "p_code": "SDQ6NH4K", "p_admin_secret": "..." }
```

응답은 JSON 객체입니다. 오류는 HTTP 400과 함께 `message` 에 `trip_not_found`, `not_allowed` 같은 코드가 옵니다.

## 1. 처음 한 번: 차량 연결

1. `create_vehicle_link` 를 인자 없이 부르면 `vehicle_secret` 과 `link_code` 가 옵니다.
2. `vehicle_secret` 은 Android Keystore로 암호화해 운전자 프로필별로 저장합니다. 다시 받을 수 없습니다.
3. 차 화면에 `https://<사이트>/link/<link_code>` QR을 띄웁니다(10분 유효). 운전자가 휴대폰으로 찍으면 연결됩니다.

## 2. 운행 만들기와 초대 QR (L1, L2 화면)

`create_trip(p_title, p_origin, p_destination, p_seats, p_rule, p_include_driver, p_vehicle_secret)` 을 부르면 새 `code` 와 `admin_secret` 이 옵니다. 차 비밀값은 꼭 넣어야 하고, 없거나 틀리면 `not_allowed` 입니다(운전자 휴대폰 비밀값으로는 만들 수 없음). 차 화면에 `https://<사이트>/t/<code>` QR을 ZXing으로 그려 띄웁니다. 운행마다 코드와 QR이 새로 생깁니다. 운행은 차 화면(주차 중)에서만 만듭니다. 운전자 휴대폰은 차를 연결하고, 차가 넘겨 준 초대와 정산을 보내는 데만 씁니다. 차에서 준비해 두고 시동을 껐던 운행과 즐겨찾기는 `get_vehicle_trips(p_vehicle_secret)` 로 다시 불러옵니다. `p_seats` 는 동승자 수 1~4명(운전자 포함 5명)이고, 벗어나면 `bad_seats` 입니다.

```kotlin
// ZXing core: 카메라 없이 QR 생성만
val matrix = QRCodeWriter().encode(url, BarcodeFormat.QR_CODE, 512, 512)
```

## 3. 동승자 장소 받아서 경유지로 넣기

`get_trip_admin` 의 `waypoints` 에 동승자 탈 곳(`pickup`)과 내릴 곳(`dropoff`)이 좌표와 함께 들어 있습니다. 탈 곳, 내릴 곳 순으로 각각 참여 순서대로 오고, 실제 들를 순서는 차가 정합니다(L3 자동, 직접 편집). 운전자의 최종 목적지는 `destination` 입니다.

```kotlin
val trip = api.getTripAdmin(code, secret)              // 정차 중에만 다시 부름 (주행 중 CPU 제한)
val stops = orderStops(trip.passengers)                // 페어풀의 들를 곳 순서
val waypoints = stops.take(2).mapIndexed { i, s ->
    RequestWaypointInfo(
        s.lat, s.lng, s.label,
        if (i == 0) WaypointIndex.FIRST else WaypointIndex.SECOND,
        "", s.address ?: s.label, "0", ""
    )
}
navi.requestRouteWithWaypoints(RouteWithWaypointsRequest(destinationOf(stops.getOrNull(2) ?: trip.destination), waypoints))
```

## 4. 운행 중 진행 상황 보내기 (동승자 M2, M2-1 화면)

| 상황 | 부를 함수 |
|---|---|
| 출발 | `set_trip_status(p_code, p_admin_secret, 'in_progress')`. 이때부터 초대 QR로 새로 참여할 수 없음. 출발한 운행은 준비로 돌아가지 않고, 정산이 끝났거나 취소한 운행은 `trip_closed` |
| 정차 중 초대 QR 다시 띄우기(즉석 동승 추가) | `set_join_open(p_code, p_admin_secret)` → 10분 동안 참여 가능. QR을 닫거나 기어가 P를 벗어나면 `set_join_open(..., p_open => false)` |
| 코스, 남은 시간, 예상 몫 | `update_progress(p_code, p_admin_secret, p_progress, p_estimates)` |
| 좌석 매칭, 탑승 | `mark_passenger(p_code, p_admin_secret, p_passenger_id, p_seat, p_boarded = true)` |
| 하차 | `mark_passenger(..., p_alighted = true)` |
| 잘못 인식(L5-2) | 안 내린 사람은 `mark_passenger(..., p_alighted => false)`, 안 탄 사람은 `p_boarded => false`(하차 기록도 함께 지워짐) |

`p_progress` 형식입니다. 남은 시간과 거리는 NaviHelper `getWaypointInfo` 의 `remainTime`, `remainDistance` 를 씁니다. 서버가 동승자마다 남의 장소와 운전자 목적지를 가려서 보여 줍니다.

## 5. 도착: 정산 올리기 (동승자 M3 화면)

`post_settlement(p_code, p_admin_secret, p_payload)` 를 부르면 운행이 끝나고 계산 결과가 동승자 페이지에 올라갑니다. 시동이 꺼져 보내지 못했다면 Room에 남겨 두었다가 다음 시동 때 보냅니다.

운행 기록은 정산이 완료될 때까지 지우지 않고 정정만 합니다. 도착 후 정산 화면에서 탑승, 하차를 고쳐 다시 계산했다면 `post_settlement(..., p_reason => '좌석 정정')` 처럼 사유와 함께 다시 보냅니다. 이전 결과는 `settlement_revisions` 에 남고, `get_trip_admin` 의 `revisions` 로 볼 수 있습니다. 그 운행에서 **한 명이라도 정산 완료**(바로 정산에서 정산 완료 체크, 폴더에서 받음 체크)면 정정 전체가 막혀 `settle_started` 오류가 납니다. 섀플리 값은 사람끼리 몫이 서로 묶여 있어 한 사람만 고정하고 나머지를 바꾸면 계산이 맞지 않기 때문입니다. `mark_passenger`(탑승, 하차, 좌석 정정)도 같습니다. 바로 정산은 정산 완료 체크를 모두 풀면(`mark_paid(..., p_paid => false)`) 다시 정정할 수 있고, 폴더는 정산을 요청한 묶음이면 `batch_locked` 입니다. 탑승 기록을 지운 동승자는 정산 완료를 풀 수 없습니다(`record_deleted`). 탑승 기록을 지운 동승자의 몫은 차가 이름을 보내도 "기록을 지운 동승자"로 저장됩니다.

```json
{
  "rule": "shapley", "include_driver": true,
  "total": 15360, "toll": 3000,
  "fuel": { "distance_km": 80.0, "efficiency_km_l": 11.0, "amount": 12360 },
  "shares": [
    { "passenger_id": "…", "name": "민지", "role": "passenger", "amount": 5110, "km": 70.0, "from": "가평 MT 숙소", "to": "망원동" },
    { "passenger_id": "…", "name": "서연", "role": "passenger", "amount": 4820, "km": 66.0, "from": "가평 MT 숙소", "to": "연남동" },
    { "passenger_id": "…", "name": "태호", "role": "passenger", "amount": 260, "km": 5.7, "from": "창천동", "to": "연희동", "alone": 310 },
    { "passenger_id": null, "name": "지훈", "role": "driver", "amount": 5170 }
  ]
}
```

- `alone` 은 선택입니다. 그 동승자가 혼자 같은 구간을 갔을 때 금액이고, M3에 "혼자 갔다면 310원이었어요"로 보입니다.
- 동승자 페이지에는 자기 줄만 구간과 거리가 보이고, 다른 사람 줄은 이름과 금액만 보입니다. 그 운행에 참여하지 않은 휴대폰에는 정산이 보이지 않습니다.
- `passenger_id` 는 그 운행의 동승자여야 합니다. 다른 운행의 동승자면 `bad_share`, 취소한 운행이면 `trip_closed` 입니다.

## 6. 도착 정산 화면(L6): 바로 정산 또는 폴더에 쌓기

정산을 올린 뒤 운전자가 L6에서 고른 방법을 `choose_settlement` 로 보냅니다. 고르기 전에는 동승자 페이지에 계좌번호가 보이지 않습니다.

| L6 선택 | 호출 | 동승자 페이지 |
|---|---|---|
| 바로 정산 | `choose_settlement(p_code, p_admin_secret, 'direct')` | M3, 계좌번호 복사(정산 중) |
| 폴더 칩 선택 | `choose_settlement(..., 'folder', p_folder_code => '<폴더 코드>')` | M5, 쌓인 금액만(요청 전) |
| + 새 카풀 폴더 | `choose_settlement(..., 'folder', p_new_folder => '출근 카풀')` | M5 |

- 폴더 칩 목록과 "쌓으면 n회 얼마" 안내는 `get_trip_admin` 의 `folders`(각 폴더의 `trips`, `amount`)와 `suggested_folder`(즐겨찾기 카풀이 마지막에 쓴 폴더)를 씁니다.
- 바로 정산에서 송금을 받으면 `mark_paid(p_code, p_admin_secret, p_passenger_id)` 를 부릅니다. 그 동승자 페이지에서 계좌번호가 내려갑니다.

## 7. 카풀 폴더 화면(L1-6, L1-7)

차량 비밀값으로도 그 차나 연결된 운전자의 폴더를 다룰 수 있습니다.

| 화면 | 호출 |
|---|---|
| 폴더 목록 | `list_folders(p_secret)` → 이름, 상태(`open` 요청 전, `requested` 정산 중), 쌓인 횟수, 받을 합계 |
| L1-6 쌓인 운행 | `get_folder_admin(p_folder_code, p_secret)` 의 `open`(운행별 내역, 사람별 합계, 운전자 몫) |
| 합쳐서 정산하기 | `request_batch(p_folder_code, p_secret)` → 사람별 금액이 확정되고, 이후 운행은 새 묶음에 쌓임 |
| L1-7 정산 중 | `get_folder_admin` 의 `requested.payments`(사람별 금액, 받았는지) |
| 정산 완료 체크 | `mark_batch_paid(p_folder_code, p_secret, p_payment_id)` → 모두 받으면 묶음이 끝나고 0원부터 다시 쌓임. 잘못 체크했으면 `p_paid => false` 로 풀고, 끝난 묶음이면 다시 정산 중이 됨(`get_folder_admin` 의 `last_done.payments`) |
| 정산 요청 취소 | `cancel_batch_request(p_folder_code, p_secret)` → 요청 전으로 돌아가고, 그사이 쌓인 운행도 다시 합쳐짐. 받음 체크가 하나라도 있으면 `settle_started` 라 먼저 체크를 풀어야 함 |
| 정산 페이지 QR(L1-7) | `get_folder_admin` 의 `requested.code` → `https://<사이트>/s/<코드>`. 묶음마다 하나이고, 기기마다 자기 몫만 보임 |
| 동승자 신고 | `get_folder_admin` 의 `requested.issues` |

## 8. 저장된 장소와 탑승 기록 지우기 (운전자만)

지우는 기능은 운전자에게만 있습니다. 동승자는 앱 밖에서 운전자에게 말하고, 운전자가 차 화면이나 운전자 페이지에서 지웁니다.

| 시점 | 호출 | 차가 할 일 |
|---|---|---|
| 탑승 기록 전 | `remove_passenger_place(p_code, p_admin_secret, p_passenger_id)` | 그 동승자의 탈 곳, 내릴 곳이 비워져 옴. 운행 중이면 남은 들를 곳으로 `requestRouteWithWaypoints` 를 다시 요청(`removeWaypoint` 는 경로 전체가 취소되어 쓰지 않음) |
| 탑승 기록 뒤 ~ 정산 완료 전 | 지울 수 없음(`record_locked`) | 확인 카드의 "잘못 인식"이나 도착 후 정산 화면에서 정정하고 `post_settlement(..., p_reason)` 로 다시 보냄 |
| 정산 완료 뒤(운행 기록 화면) | `delete_ride_record(p_code, p_admin_secret, p_passenger_id)`. 가능 여부는 `get_trip_admin` 의 동승자별 `settle_done` | 그 동승자의 탑승, 하차 위치와 이름만 지워짐. 정산 금액과 정정 내역은 남고 그 몫은 "기록을 지운 동승자"로 표시 |
| 즐겨찾기 화면의 주소 옆 x | `remove_member_place(p_carpool_code, p_secret, p_member_id)`. 운행 기록과 관계없이 다음 운행에 미리 채울 장소만 지움 |

## 9. 동승자 빼기(L2/P2)와 운전자 정보 입력(L1-9)

L1-9는 "운전자 정보 입력" 화면입니다. 주차 중에 운전자 이름, 휴대폰 번호 뒤 4자리, 정산 받을 계좌를 한 번에 넣습니다. 이름과 뒤 4자리는 운전자가 자기 휴대폰에서 "내 휴대폰으로 보내기"(10절)를 열 때 씁니다.

| 화면 | 호출 |
|---|---|
| 초대 응답의 동승자 행 x(확인 없이 바로 빼기) | `remove_passenger(p_code, p_admin_secret, p_passenger_id)`. 탑승 기록 전에만 가능하고, 빠진 사람의 들를 곳을 뺀 남은 들를 곳으로 `requestRouteWithWaypoints` 를 다시 요청. 동승자 쪽에는 빠지기 기능이 없음 |
| 운전자 정보 불러오기 | `get_driver_info(p_vehicle_secret)` → `{ name, phone4_set, bank }`. 뒤 4자리는 해시로만 저장해 돌려주지 않고, 넣었는지(`phone4_set`)만 알려 줌 |
| 저장하기: 이름, 뒤 4자리 | `set_driver_info(p_vehicle_secret, p_name, p_phone4)`. 처음에는 뒤 4자리가 꼭 필요하고(`phone4_required`), 그 뒤에는 `p_phone4 => null` 이면 전에 넣은 값을 그대로 둠 |
| 저장하기: 계좌([필수] 동의) | `set_bank_account(p_vehicle_secret, p_consent => true, p_bank_name, p_bank_account, p_account_holder)` |
| 계좌 지우기 | `set_bank_account(p_vehicle_secret, p_consent => false)` → 서버에서 바로 삭제되고 동승자 페이지에서도 내려감 |

운전자 정보는 차 비밀값으로만 넣을 수 있습니다. 운전자 웹에는 입력 화면이 없습니다. 차를 운전자 휴대폰과 연결하기 전에 넣었으면, 연결할 때 그 운전자에게 옮겨집니다.

## 10. 내 휴대폰으로 보내기 (L2/P2, L6, L1-7)

차에는 문자나 카카오톡을 보낼 앱이 없어서, 차 화면의 버튼은 초대와 정산 정보를 **운전자 휴대폰으로** 넘깁니다. 운전자는 휴대폰에서 "QR과 링크 공유하기"로 QR 이미지와 링크를 함께 단톡방이나 문자에 보냅니다.

| 화면 | 버튼 | 호출 | 휴대폰에 생기는 카드 |
|---|---|---|---|
| L2/P2 초대 QR과 응답(출발 전, 운행 중) | 내 휴대폰으로 보내기 | `queue_trip_share(p_code, p_admin_secret)` | 초대: 운행 이름, 출발지, 남은 자리, 참여한 사람 이름(장소 없음), 운행 링크 `/t/<코드>` |
| L6 도착 정산(바로 정산을 고른 뒤) | 내 휴대폰으로 보내기 | `queue_trip_share(p_code, p_admin_secret)` | 이 운행: 총비용, 사람별 금액과 구간, 받았는지, 계좌, 운행 링크 `/t/<코드>` |
| L6 도착 정산(폴더에 쌓기를 고른 뒤) | 내 휴대폰으로 보내기 | `queue_trip_share(...)` | 이 운행: 사람별 금액과 구간, 쌓인 폴더 이름(계좌 없음). 그 폴더가 이미 합쳐서 정산 중이면 묶음 카드로 보냄 |
| L1-7 카풀 폴더 정산 중 | 내 휴대폰으로 보내기 | `queue_batch_share(p_folder_code, p_secret)` | 묶음: 받을 합계, 사람별 합계와 횟수, 운행별 내역(구간 포함), 계좌, 정산 페이지 링크 `/s/<코드>` |

- 고르기 전에 누르면 `not_chosen`, 정산 중인 묶음이 없으면 `no_request` 입니다.
- 운전자는 휴대폰에서 그 운행 링크(또는 정산 페이지)를 엽니다. 출발 전이면 차 화면의 초대 QR을 자기 휴대폰으로 찍고 M1의 "운전자라면 여기서 초대를 공유할 수 있어요"를 누릅니다. 그다음 M1-1 확인 화면에 **L1-9에서 넣은 이름과 뒤 4자리**를 넣습니다. 동승자 확인과 같은 칸을 쓰고, 틀린 횟수도 함께 셉니다(1시간에 기기당 5번, 페이지 전체 30번, 하루 페이지 전체 100번).
- 그 휴대폰 화면은 **보기 전용**입니다. 정산 방법, 정산 완료, 금액은 바꿀 수 없고, 그 휴대폰을 동승자로 묶지도 않습니다. 고치는 일은 모두 차 화면에서 합니다.
- 초대 카드는 운행이 끝나면 사라지고, 정산 카드는 그 운행의 동승자가 모두 정산 완료되거나, 묶음이 끝나면 사라집니다. 정산 요청을 취소하면 묶음 카드도 지워지고, 다시 요청하면 다시 보내야 합니다.
- 푸시 알림은 보내지 않습니다. 운전자가 다음에 링크를 열 때 카드가 보입니다.

## 12. 화면별로 부르는 함수

`p_secret` 자리에는 차 비밀값(`vehicle_secret`)을 넣습니다. 운행 하나를 다루는 함수(`p_admin_secret`)도 그 운행이 이 차에 연결된 운전자의 것이면 차 비밀값으로 됩니다. 세로 화면(P)은 같은 번호의 가로 화면(L)과 같은 함수를 부릅니다.
