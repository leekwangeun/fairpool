# 페어풀(FairPool) : 공정한 카풀 정산

함께 탄 거리와 경로로 기름값과 통행료를 공정하게 나누는 Pleos Connect 차량용 카풀 정산 앱입니다.

## 앱 소개

- **차 화면에서 운행을 만들고 초대 QR을 띄웁니다.** 동승자는 앱 설치 없이 QR이나 링크로 들어와 탈 곳과 내릴 곳을 고르고, 차는 그 장소를 내비 경유지로 받습니다.
- **주행 중 기록은 차가 남깁니다.** 좌석과 문 신호로 누가 언제 타고 내렸는지 기록하고, 정차 중에만 확인 카드를 띄웁니다.
- **도착하면 공정 정산(섀플리 값)으로 나눕니다.** 함께 타서 아낀 돈을 각자 만든 거리만큼 나누고, 돌아간 거리는 만든 사람이 더 냅니다. 탄 거리 비례, N분의 1도 고를 수 있습니다.
- **바로 정산하거나 카풀 폴더에 쌓아 한 번에 정산합니다.** 동승자 페이지에는 정산 중에만 계좌번호가 보이고, 페어풀은 송금하지 않습니다.
- **계정이 없습니다.** 운전자, 동승자, 차는 각자 기기에 둔 무작위 비밀값으로 구분하고 서버에는 해시만 저장합니다.

## 저장소 구성

| 폴더 | 내용 |
|---|---|
| `apk/` | 제출용 release APK (`팀명_페어풀_release.apk`) |
| `car/` | 차량 앱 (Kotlin, Pleos Connect) |
| `web/` | 휴대폰 웹: 동승자 페이지, 운전자 휴대폰의 차 연결과 보내기 (React, TypeScript, Vite, Tailwind CSS, MapLibre) |
| `supabase/migrations/` | 운행 서버의 DB 테이블과 서버 함수(SQL) |
| `supabase/tests/` | 실제 마이그레이션을 PGlite(Node에서 도는 Postgres)로 돌리는 테스트 47개 |
| `devserver/` | Supabase 없이 쓰는 로컬 개발 서버. 같은 마이그레이션을 Supabase와 같은 주소 모양(`POST /rest/v1/rpc/<함수>`)으로 열고 시연 데이터를 넣음 |
| `docs/` | 서버 설계, 차량 앱 연동 방법(화면별로 부르는 함수) |

## 실행 방법

### 1. 차량 앱 (APK)

1. Pleos Connect 에뮬레이터(또는 차량)를 켭니다.
2. `apk/팀명_페어풀_release.apk` 를 설치합니다.

```bash
adb install apk/팀명_페어풀_release.apk
```

3. 차 앱이 붙을 서버를 켭니다(아래 2). 에뮬레이터에서는 PC의 개발 서버가 `http://10.0.2.2:54321` 로 보입니다.

소스에서 빌드하려면 `car/` 폴더를 Android Studio로 엽니다.

### 2. 로컬 개발 서버 (차 앱과 휴대폰 웹이 함께 쓰는 서버)

Node.js 20 이상이 필요합니다. 자세한 내용은 [devserver/README.md](devserver/README.md)에 있습니다.

```bash
cd devserver
npm install
npm run reset   # DB를 새로 만들고 시연 데이터(지훈 차와 계좌, 출근 카풀 폴더 16회, 동아리 MT 귀갓길 준비 운행)를 넣음
npm start       # http://localhost:54321, 에뮬레이터는 http://10.0.2.2:54321
```

시연 데이터의 차 비밀값과 운행 코드는 `devserver/data/seed.json` 에 저장됩니다(git에는 올리지 않음).

### 3. 휴대폰 웹

```bash
cd web
npm install
npm run dev     # http://localhost:5173
```

- 아무 설정 없이 실행하면 같은 SQL을 브라우저 안에서 돌리는 **데모 모드**로 동작합니다(오른쪽 위 "데모 모드" 표시). 차 화면을 대신하는 시연용 페이지(`/`, `/new`, `/d`, `/f`)의 "시연 도구"로 차가 보내는 진행 상황과 정산을 흉내 낼 수 있습니다. 이 페이지들은 실제 사용자 경로에는 나오지 않습니다.
- 로컬 개발 서버에 붙이려면 `web/.env.local` 에 `VITE_API_URL=http://localhost:54321` 을 넣습니다.
- 같은 와이파이의 휴대폰에서 열려면 개발 서버가 출력하는 PC 주소(`http://<PC의 IP>:5173`)로 접속합니다.

### 4. 테스트

```bash
cd supabase && npm install && npm test     # 서버 함수 47개 시나리오
cd devserver && npm install && npm test    # 개발 서버 HTTP 응답
cd web && npm run build                     # 타입 검사와 빌드
```

## 테스트 환경과 필요한 설정

| 항목 | 내용 |
|---|---|
| 차량 | Pleos Connect 에뮬레이터 (Android Automotive), 가로 1682×1210 단독 실행과 세로 841×1210 분할 화면 |
| 휴대폰 | 모바일 브라우저(Chrome 모바일 화면 390 폭으로 확인). 앱 설치 없음 |
| PC | Windows 11, Node.js 24 (20 이상), npm |
| 서버 | 로컬 개발 서버(`devserver`, 포트 54321) 또는 Supabase |

| 설정 | 어디에 | 값 |
|---|---|---|
| `VITE_API_URL` | `web/.env.local` | 로컬 개발 서버 주소. 넣으면 Supabase보다 먼저 씀 |
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | `web/.env.local` 또는 배포 환경 변수 | Supabase 프로젝트 주소와 anon key. 모두 비우면 데모 모드 |
| `VITE_PUBLIC_BASE_URL` | 같음 | QR에 찍힐 사이트 주소 (비우면 현재 주소) |
| `PORT`, `HOST` | 개발 서버 환경 변수 | 기본 54321, 0.0.0.0 |
| 서버 주소 | 차 앱 | 에뮬레이터 `http://10.0.2.2:54321`, 배포 뒤에는 Supabase 주소 |

- 장소 검색(Photon)과 지도 타일(OpenFreeMap)은 키 없이 인터넷 연결만 있으면 됩니다.
- 윈도우에서 같은 와이파이의 휴대폰으로 개발 서버에 붙을 때는 방화벽에서 Node를 허용해야 합니다.

## 운행마다 전용 페이지와 QR

운행을 만들면 그 운행만의 코드(예: `SDQ6NH4K`)가 발급되고, 동승자 페이지 주소 `https://<사이트>/t/SDQ6NH4K` 와 그 주소의 QR이 생깁니다.

```
차 화면(L1 운행 만들기, L2 초대 QR) ──create_trip──▶ 운행 서버 ──▶ 코드, 관리 비밀값
        │
        └─ QR: https://<사이트>/t/<코드> ──▶ 동승자 휴대폰 ──join_trip(탈 곳, 내릴 곳 좌표)──▶ 운행 서버
                                                                                  │
차량 앱 ◀──get_trip_admin(코드, 관리 비밀값)── 동승자 장소 ──▶ NaviHelper 경유지 ◀┘
```

- 사이트는 하나이고, 운행마다 주소와 QR만 새로 생깁니다. 사이트를 매번 새로 배포하지 않습니다.
- 코드는 헷갈리는 글자(0, O, 1, I, L)를 뺀 8자리입니다(약 8,500억 가지라 대입해 맞히기 어려움).
- 출발한 운행에는 새 동승자가 들어올 수 없습니다. 차가 멈춘 뒤 차 화면에 초대 QR을 다시 띄우면 10분 동안만 열립니다. 이미 참여한 사람은 타기 전까지 자기 장소를 고칠 수 있습니다.
- 운행은 차 화면(주차 중)에서만 만들고 고칩니다. 서버도 운행 만들기(`create_trip`, `recreate_trip`)를 차 비밀값으로만 받고 운전자 휴대폰 비밀값은 거절합니다. 운전자 휴대폰은 차 연결과, 차가 넘겨 준 초대와 정산을 보내는 데만 씁니다.
- 운행을 만든 차만 관리 비밀값을 가집니다. 동승자는 코드로 참여만 할 수 있습니다.
- 한 운행에는 동승자 4명까지(운전자 포함 5명) 탈 수 있습니다.

## 화면 (휴대폰 웹)

동승자 화면은 피그마 시안 "동승자 휴대폰 웹"(M1~M6-1)을 구현했습니다.

| 주소 | 시안 | 내용 |
|---|---|---|
| `/t/:code` | M1 | 초대, 이름, 휴대폰 뒤 4자리, 탈 곳(출발지에서 같이 타요, 가는 길에 태워 주세요), 내릴 곳 검색, 장소 저장 안내 |
| `/t/:code` | M1-1 | 다른 휴대폰에서 열면 이름과 뒤 4자리로 확인. 운전자가 차 화면(L1-9)에 넣은 이름과 뒤 4자리를 넣으면 "내 휴대폰으로 보내기" 카드(보기 전용)가 열림 |
| `/t/:code` | M1-2 | 운전자 휴대폰(보기 전용): 차에서 "내 휴대폰으로 보내기"로 보낸 초대와 정산 카드. "QR과 링크 공유하기"로 QR 이미지와 링크를 함께 보냄 |
| `/t/:code` | M2 | 탑승 전: 도착까지 남은 시간, 차 위치 지도, 예상 내 몫, 코스(다른 동승자 장소와 운전자 목적지는 가림) |
| `/t/:code` | M2-1 | 탑승 후: 내릴 때까지 남은 시간, 위치 공유 꺼짐 안내, 코스 |
| `/t/:code` | M3 | 바로 정산: 내 몫, 나눈 방법, 총비용, 모두의 몫, 저장된 장소, 정산 중일 때만 계좌번호 복사 |
| `/t/:code` | M3-1 | 정산에 문제가 있어요: 문제 종류와 남길 말. 차 화면 요청 목록(L1-8)으로 감 |
| `/t/:code` | M5 | 카풀 폴더에 쌓인 금액(요청 전): 지금까지 n회, 오늘 더해진 금액, 쌓인 운행 |
| `/s/:code` | M6 | 합쳐서 정산하기를 누를 때 묶음마다 하나 생기는 정산 페이지(정산 중): 내 분담액, 묶음 전체 횟수와 총비용, 함께 탄 사람 이름과 몫, 계좌번호 복사. 다른 휴대폰은 이름과 뒤 4자리로 확인 |
| `/s/:code` | M6-1 | 합쳐서 정산 완료: 계좌번호는 내려가고, 폴더는 0원부터 다시 쌓임 |
| `/t/:code/how` | M4 | 계산 방법 |
| `/c/:code` | - | 즐겨찾기 카풀 고정 링크. 최신 운행으로 연결, 이번 달 분담액 |
| `/link/:code` | - | 차 화면의 연결 QR로 운전자 휴대폰과 차를 연결 |

## 배포

### 1. Supabase (운행 서버)

1. supabase.com에서 프로젝트를 만듭니다(무료 요금제).
2. Database > Extensions에서 `pg_cron`을 켭니다(끝난 운행의 위치 자동 삭제용).
3. 마이그레이션을 올립니다.

```bash
npx supabase login
npx supabase link --project-ref <프로젝트 ref>
npx supabase db push
```

4. Settings > API에서 Project URL과 anon key를 확인합니다. anon key로는 테이블을 직접 읽을 수 없고, 정해진 함수만 부를 수 있습니다.

### 2. Vercel (휴대폰 웹)

1. vercel.com에서 이 GitHub 저장소를 가져옵니다.
2. Root Directory를 `web`으로 지정합니다.
3. 환경 변수 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_PUBLIC_BASE_URL` 을 넣습니다.

## 외부 데이터

- 지도: [MapLibre GL JS](https://maplibre.org/)와 [OpenFreeMap](https://openfreemap.org/) 타일, 데이터 © OpenStreetMap 기여자
- 장소 검색: [Photon](https://photon.komoot.io/)(OpenStreetMap 검색). 카카오 로컬 검색을 서버 함수로 붙이면 교체할 수 있게 `web/src/api.ts`의 `searchPlaces` 한 곳에 모아 두었습니다.

## 개인정보

- 회원가입, 휴대폰 번호, 계정이 없습니다. 운전자, 동승자, 차는 각자 기기에 둔 무작위 비밀값으로 구분하고 서버에는 해시만 저장합니다. 휴대폰 뒤 4자리도 운행 ID와 섞은 해시로만 저장합니다.
- 동승자의 탈 곳과 내릴 곳은 운전자(와 연결된 차)만 봅니다. 다른 동승자에게는 "동승자 1명 내림"처럼 가려서 보이고, 운전자의 목적지도 보이지 않습니다.
- 차 위치는 그 동승자가 타기 전까지만 보입니다.
- 정산 결과는 그 운행에 참여한 휴대폰에만 보입니다. 다른 사람의 몫은 금액만 보이고 어디서 타고 내렸는지는 빠집니다.
- 정산이 끝나면 좌표를 동네 수준(약 1km)으로 줄이고, 24시간 뒤에는 장소를 지웁니다. 즐겨찾기 카풀로 저장된 운행만 다음 운행을 위해 탈 곳과 내릴 곳을 남깁니다. 참여 화면에서 미리 알립니다. 지우는 기능은 운전자에게만 있고, 동승자는 앱 밖에서 운전자에게 말하면 됩니다. 일회성 운행은 남기지 않습니다.
- 운행 기록은 정산이 완료될 때까지 지울 수 없고 정정만 합니다. 정산이 완료되면 운전자가 탑승 기록을 지울 수 있고, 지워도 정산 금액과 정정 내역은 남고 그 몫은 이름 없이 "기록을 지운 동승자"로 표시돼 합계가 맞습니다.
- 운전자 이름, 휴대폰 뒤 4자리, 받을 계좌는 주차 중 차 화면(L1-9)에서만 넣습니다. 계좌는 동의한 경우에만 암호화해 저장하고, 실제로 탄 사람의 정산이 정산 중일 때만 보여 줍니다. 정산이 끝나면 그 사람 페이지에서 내려갑니다.

자세한 내용은 [docs/서버_설계.md](docs/서버_설계.md), 차량 앱 쪽 호출 방법은 [docs/차량앱_연동.md](docs/차량앱_연동.md)에 있습니다.
